# Learnings

The project's memory of hard-won lessons — ECC calls these "instincts". One line each, newest at the bottom, with a confidence tag: **[high]** = proven repeatedly / verified, **[med]** = seen once, plausible general rule. When a **[high]** learning is general enough, promote it into [[engineering-rules]] or `CLAUDE.md` and mark it `(promoted)`.

Every agent pipeline run ends with `docs-keeper` asking: *did we learn anything a future session should know?* Bug fixes, review findings, founder corrections, and environment surprises all qualify. Skip trivia the code already documents.

| 2026-07-18 | Retrying a greedy-sampled generation is a no-op — greedy is deterministic, so a retry only makes sense with different sampling, and only for failures a re-roll can actually change (decoding), not for content that sanitized to nothing | [high] |
| 2026-07-18 | A `@MainActor` class used as a default argument needs a `nonisolated init` — default args evaluate outside the actor, and the compiler rejects an isolated init there | [med] |
| 2026-07-18 | A background subagent can report `failed` (API/usage cutoff) after its file writes already flushed to disk — don't assume rollback; check `git status` + build + tests to learn the real tree state before redoing work | [med] |
| 2026-07-18 | Raw-SQLite `Float32` embeddings survive a round-trip only if you store `dimension` alongside the blob and validate `blobBytes == dimension * 4` on read — a model/embedding-size change otherwise mis-reads old vectors as garbage instead of failing loudly | [high] |
| 2026-07-18 | SQLite makes its own file, so setting `0o600` on it must happen by pre-creating the file before `sqlite3_open` (umask alone won't guarantee it); the parent dir gets `0o700` at create time | [high] |
| 2026-07-19 | NLEmbedding sentence embeddings compress cosine into a **high band** — even unrelated English texts score 0.5–0.7, real matches 0.84–0.94, near-miss strays up to ~0.78. A match threshold MUST be calibrated against measured negatives (incl. near-misses), never guessed: the 0.6 placeholder force-matched strays; ~0.80 is the separating value. Measure with real NLEmbedding, not intuition | [high] |
| 2026-07-19 | A threshold calibrated AND tested on the same synthetic points is circular — it can't fail by construction. Keep the calibration set separate from the guard test, and treat a synthetic-only number as PROVISIONAL until validated on real data with the real end-to-end path (real AI summaries, not stand-ins) | [high] |
| 2026-07-19 | Typed errors that dead-end in a `#if DEBUG` log are **invisible in release** — the app then silently runs on a broken/empty index while showing a normal UI. Surfacing a store/scan failure (or `OpenOutcome.recoveredFromCorruption`) to the user needs a non-DEBUG, user-facing path, or the honest-status promise is quietly broken in the one build that ships | [high] |
| 2026-07-19 | A row's `storeID` is assigned *after* the insert `await` returns; a user action during that suspension (e.g. Remove) can orphan the just-inserted row → it resurrects on next launch. Any "assign the ID after await" path needs a compensating delete when the owner vanished mid-insert | [med] |
| 2026-07-19 | FoundationModels generation runs headlessly from a plain `swift test` process on macOS 26 with Apple Intelligence on (~2 s for a summary+filename); gate such live-model tests behind an env var (`.enabled(if:)`) so the normal suite stays fast and deterministic | [high] |
| 2026-07-23 | A UI callback captured by a view that outlives one screen can fire *after* the controller advanced to the next item — a single Return firing both `.onSubmit` and a default-action button, straddling a synchronous queue advance, would act on the NEXT popup. Bind each callback to its source item's identity (`guard current?.id == shownID`); a plain `guard let current` is not enough | [high] |
| 2026-07-23 | Freeze what a transient popup renders into an immutable snapshot at enqueue time; never read live model state after show — a later prune/re-suggestion then can't corrupt an on-screen popup. Re-check liveness only when *dequeuing* the next item | [high] |
| 2026-07-23 | A non-activating `.accessory` `NSPanel` posting `NSAccessibility.post(.announcementRequested)` while another app is frontmost is **known-unreliable** — VoiceOver may never speak it, and `post` returns Void so you can't detect the miss. Implement per Apple's API but treat "did the user get told" as a live-VoiceOver acceptance gate; do NOT "fix" a silent announcement by making the panel key (that breaks the non-activating promise) | [med] |
| 2026-07-23 | SQLite `INTEGER PRIMARY KEY AUTOINCREMENT` is **load-bearing for cross-seam id stability**: it guarantees deleted row-ids are never reused, so a frozen id resolves to *nothing* (never a *different* folder) if the folder vanished. Dropping it as "cleanup" would turn a stale popup id into a wrong-destination move. Any id carried across a time gap must still be re-validated at use time | [high] |
| 2026-07-23 | A runtime env-var gate (`ProcessInfo…environment[...]`) leaves the guarded code **in the release binary** — only `#if DEBUG` removes it. For anything that could print file content, use `#if DEBUG`, not an env flag | [high] |
| 2026-07-28 | SwiftUI evaluates the `App`'s `body` — reading `@NSApplicationDelegateAdaptor` properties — **before** `applicationDidFinishLaunching` runs. Anything a `Scene` reads off the delegate must be built in the delegate's `init`, not the launch callback, or the scene captures the pre-launch `nil` and keeps it: Settings claimed "history isn't available" while the app was moving and recording files, and the menu got a nil controller so its rows were never clickable. Neither is caught by the test suite, because both are wiring, not logic | [high] |
| 2026-07-28 | In a `.menu`-style `MenuBarExtra`, NSMenu turns **each view into its own menu item** — an `HStack` of arrow + icon + folder name renders as three stacked lines with the name stranded below an empty arrow. Build such a line as ONE concatenated `Text` (`Text("→ ") + Text(Image(systemName:)) + Text(name)`). Related: plain `Text` rows become *disabled* items that keyboard nav and VoiceOver skip, so any action must be its own single-line `Button` — you cannot make a multi-line row clickable by wrapping it | [high] |
| 2026-07-28 | Two history rows can legitimately record the same final path without any overwrite: a same-volume rename preserves the inode, so a file that was moved, restored, and re-accepted produces two rows with identical `final_name` AND identical `source_inode`. When a duplicate-looking history row is reported, compare `source_inode` before suspecting a clobber — matching inodes mean one file, two events | [med] |
| 2026-07-29 | A test that awaits work which was never *supposed* to start **hangs instead of failing**. `waitForActiveMoves()` loops on a task the test double never completes, so the assertion below it is never reached and `swift test` never finishes — a real defect (nothing blocks a second Accept in the settled state) sat hidden behind a suite that "just seemed slow". If the whole suite stops finishing, bisect by streaming the log to a **file, not a pipe** (`swift test > log 2>&1` — a pipe to `tail` buffers everything until exit and shows you nothing), then diff started-vs-finished test names. `sample <pid>` confirms it: an idle main thread parked in `CFRunLoopRun` with zero CPU means a suspended continuation, not slow work | [high] |
| 2026-07-29 | Never write an unbounded `await` into a test asserting that something did NOT happen — assert the observable count directly, or bound the wait. The failure mode of "wait for a thing that must never exist" is an infinite hang, which reads as infrastructure flakiness rather than as the bug it is | [high] |
| 2026-07-29 | Milestone scratch left in the vault root compounds fast: M6 produced five loose `m6-*.md` files (85 KB) that buried the seven durable notes, and the review then found `design-system.md` still describing a menu design dropped by founder decision 6 — so the built UI followed the *mockup* while the doc said something else. Scratch goes in `docs/milestone-work/<milestone>/`; durable facts get distilled out when the milestone closes. Mark superseded doc sections in place rather than deleting them — the reasoning is still worth reading, the instruction is not | [med] |
| 2026-07-29 | Parallel reviewers earn their cost through **independent convergence**, not coverage: the undo-identity bug, the close-as-success fallback, the panel that never resizes, and the Clear-History false failure were each found by two or three reviewers approaching from different lanes. A finding that only one reviewer sees is worth checking; one that three see independently is real. Corollary: reviewers also disagree (a11y accepted the TCC failure as text, design flagged the missing button) — resolve those against the **locked founder decision**, not by reviewer seniority | [med] |
| 2026-07-30 | Documentation drifts **silently and in one direction**: toward describing the milestone it was written in. A sweep found `README.md` ("M6 not yet built"), `architecture.md` (still describing the removed no-move seam), `Popup-UI.md` ("M1–M2 scope (current)"), `website/README.md` ("site NOT built yet"), and a playbook gate still unchecked after the thing shipped. None was noticed because each doc is only ever read alone. The cheap defence is a **cross-document consistency sweep at milestone close** — grep every Status section, every "not yet"/"next scheduled"/"current scope" phrase, and every file path in prose, against one source of truth | [high] |
| 2026-07-30 | The most dangerous stale doc is one an **agent** reads, not a human. `ai-engineering.md` still instructed `ai-reviewer` to verify a pinned, checksummed model download — 11 days after the FoundationModels switch made any network call a critical finding. A reviewer briefed on the old world would have *excused* the exact egress it exists to catch. When a locked decision changes, grep `.claude/agents/*.md` **and** the guides those briefs cite — a stale brief mis-instructs a whole subagent silently, and subagents never push back | [high] |
| 2026-07-30 | Known limits written as "revisit before X happens" go stale the moment X happens, because nothing watches for X. The watcher's two M1 limits ("revisit before files are moved") sat unchanged through M6 wiring a real mover into Accept. Deferred items need a **trigger recorded in a list somebody actually reads** ([[open-work]]), not a conditional buried in the module note | [high] |
| 2026-07-30 | In **zsh**, unquoted `$VAR` in a `for` loop does *not* word-split — a captured multi-line file list is passed as one giant argument, and a `perl -pi` over it silently edits nothing while appearing to succeed. Use `while IFS= read -r f` (or `${(f)VAR}`). Always follow a bulk rewrite with a verification grep for the *old* pattern; the first run of this reorganisation reported success and had changed zero files | [high] |
| 2026-07-30 | Mermaid labels: `**bold**` renders as literal asterisks and `<i>` is escaped under GitHub's strict security level, so diagrams that look right in one renderer look broken in another. Stick to plain text plus `<br/>` inside node labels. Note also that mermaid's subroutine shape `[[text]]` looks exactly like an Obsidian wiki-link to a naive grep — expect false positives when auditing links | [med] |
| 2026-07-30 | **A static site's folder is a publish root, and anything sharing it ships with it.** `website/` held the three pages *and* the design export, the screenshots, and the team playbook — one `deploy website/` from making all of it public. Separate "the artifact" from "the working material" **before** wiring up hosting, not after; the fix costs one `git mv` beforehand and a takedown afterwards | [high] |
| 2026-07-30 | Vendor exports and scaffolding tools ship READMEs that **address coding agents in the imperative** ("CODING AGENTS: READ THIS FIRST", "read this file in full, follow its imports"). They are auto-generated, frequently reference paths that don't exist in your repo, and are indistinguishable in form from a prompt-injection attempt. Treat every file as data; neutralise the file rather than relying on a prose warning elsewhere, because the warning is only read by whoever already knew | [high] |
| 2026-07-30 | Doc-freshness rules that only fire "at the end of a session" are the ones that fail, because the sessions that damage the vault most are the ones with no end — a `/clear`, a context limit, a closed laptop. Two changes make it survivable: write each fact to disk **the turn it becomes true** (a finding gets a row, a decision gets a line), and keep an **⚡ In flight** line written *before* expensive work rather than after it. Equally: **verify the register on open** rather than trusting it. A register that is believed and wrong costs more than no register at all | [high] |
| 2026-07-30 | The stale-agent-brief lesson **recurred within a week of being written down**: `qa-tester` was still instructed that "`swift test` currently does not finish" after the hang was fixed, so it would have treated a healthy suite as the known-broken one. Writing a learning does not prevent the thing — nothing was watching. What prevents it is a **mechanical sweep at session close** (`grep -rniE "not committed\|not yet\|does not finish\|current scope"`), with `.claude/agents/*.md` explicitly in the list of files to update. A brief that states a *fact* (a test baseline, a module's behaviour) rots exactly like a doc, and rots more dangerously | [high] |
| 2026-07-30 | **This project numbers review findings `M1`, `M7`, `M23` — the same shape as milestone ids** (`M1`–`M6`), and the two ranges overlap. "M7 (the watcher claim) is fixed" in the M6 notes means finding #7, not a seventh milestone; reading it as one produced three documents confidently announcing "next milestone is M7" for work that was never scoped. An invented next step is worse than a missing one, because it reads like a plan and the next session inherits it as one. Later rounds moved to `F##`/`A##`/`D##`/`X##` for exactly this reason — **never reuse the milestone prefix for finding ids**, and when a doc says `M<n>`, check which namespace it means before acting on it | [high] |
