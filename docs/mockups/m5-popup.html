M5 — Suggestion popup

mockup for approval · nothing here is live

A small panel slides in at the top-right of the screen once a new download has been understood on-device. It shows the file's current name, a suggested better name you can edit, and a suggested destination folder — with Accept and Dismiss. Ignore it and it fades after about 15 seconds, doing nothing. A file is only ever touched when you click Accept.

Important for this milestone: in M5 even Accept moves nothing yet — the actual rename and move arrive next milestone. So the panel's Accept is designed to be honest about that (see the "After Accept" panel in section 2). If the AI has no suggestion at all, no popup appears — the app simply stays quiet.

  • Glance path, top to bottom: the dimmed current name (what it is now) → the bright editable field (the proposed name) → the blue folder (where it would go) → Accept, the one filled button.
  • Editing is inline. There is no separate Edit button — the suggested name lives in a real text field. Click it and type. The faint pencil is only a hint that the AI's guess is yours to change.
  • Dismiss is deliberately quiet (borderless, grey) so Accept is unmistakably the primary action. It never looks like an ad or a system alert: opaque window surface, app name at the top, no marketing, no big icon.
  • The blue folder icon appears only on the destination line — the same rule as the menu, so "where it goes" is findable at a glance.
Motion — please picture it Entrance: slides in ~12 px from the right while fading up, ≤ 250 ms, ease-out — no bounce, no spring. Exit reverses the same way. Auto-dismiss: a plain fade-out after ~15 s of no interaction. Under the system "Reduce Motion" setting it simply cross-fades in place (no slide). Return accepts, Esc dismisses.

Founder decision — the post-Accept moment In this milestone Accept performs no file action, so the panel must not pretend it did. My recommendation is the calm confirmation above: the content cross-fades to "Suggestion accepted" for about 1.2 s, then the panel slides out. The small second line ("No file has been moved or renamed yet") is optional — it makes the honesty explicit but is a touch more downbeat on camera. The one thing we will not do is show a checkmark or "Moved to Invoices," because that would be untrue until next milestone. If you'd rather the demo look fully finished, the alternative is simply not clicking Accept on camera and demoing up to the popup. Your call on: (a) keep the confirmation, (b) drop the second line, or (c) skip Accept in the video.

Founder decision — show a reason, or not A "why" line can build trust in the demo — it shows the AI actually understood the file. The trade-offs: it adds reading time (works against the under-2-second glance) and it puts a hint of the file's contents on screen, which the menu deliberately avoids. My default stays name + destination only; adopt this only if the added trust is worth the extra line.
